Every invoice. Checked.

AvixCheck flags supplier invoice discrepancies against purchase orders and agreed prices before payment. It reads PDF invoices, matches them to suppliers, PO lines and dated price agreements, and routes every difference or uncertainty to a person.

How an invoice moves through AvixCheck

One Next.js application plus a background worker. Every step is a durable, idempotent job, and nothing uncertain is passed silently.

  1. Import

    Suppliers, purchase orders, price agreements, approved charges and receipts from CSV templates, with a preview and row-level errors.

  2. Upload & scan

    PDF invoices go to private storage. ClamAV scans them first; infected files are quarantined.

  3. Extract

    AI reads the header and line items. Low-confidence or incomplete results go to manual correction.

  4. Match

    Supplier, PO, PO lines and the agreement in force on the invoice date. Weak matches go to review.

  5. Check

    Deterministic decimal rules compare expected and actual values and record the versions used.

  6. Review & export

    Assign exceptions, record decisions, accept authorised variances with reasons, export to CSV.

What it checks

Financial checks are deterministic code with explicit rounding and configurable tolerances. AI is used only to read documents. Each discrepancy amount is potential exposure, kept separate from confirmed corrections.

CheckFlags when
price_varianceUnit price is above the dated agreement price (or PO price) beyond tolerance.
missing_discountAn agreement discount applies at the billed quantity but was not given.
quantity_excessQuantity exceeds the PO line's remaining balance.
receipt_quantity_exceededQuantity exceeds what was received, checked only when receipt data exists.
po_balance_exceededCumulative billing across invoices goes above the PO value.
arithmetic_errorQuantity × price, line totals, subtotal, tax or total do not add up.
duplicate_invoiceSame document, same supplier and invoice number, or same supplier, total and date.
unapproved_chargeA freight, handling or other charge has no approved charge, or exceeds its limit.
currency_mismatch / unit_mismatchInvoice currency or unit differs from the PO, agreement or supplier.
missing_reference / conflicting_referenceSupplier, PO, PO line or agreement is missing, ambiguous, closed or cancelled.
missing_dataRequired invoice or line fields are missing.

Credit notes restore PO balance, partial invoices bill across PO lines, and amended POs are versioned. Retries and concurrent checks cannot double-count a balance. Rule details

Security and data

Invoices are supplier-authored, so their contents are treated as untrusted input throughout.

  • Tenant isolation with forced Postgres row-level security and same-organisation triggers on every cross-table reference.
  • Private documents in S3-compatible storage, served only through short-lived signed URLs after an org and permission check.
  • Malware scanning with ClamAV before any processing; upload size limits and PDF validation.
  • Managed sign-in with Clerk (MFA, sessions), rate limits, CSP and security headers.
  • Append-only audit log for imports, edits, checks, assignments and decisions.
  • Operations — structured logs with redaction, Sentry, retention with legal hold, verified backups and restore drills.

Run it locally

Requires Node.js 20.11+ and Docker. See the README for details.

# Postgres, S3-compatible storage and ClamAV
cp .env.example .env.local
docker compose up -d
npm ci
npm run db:migrate
npm run dev       # web app on :3000
npm run worker    # background jobs, in a second terminal

# Checks
npm test          # unit and integration tests against a real Postgres
npm run test:e2e  # browser end-to-end tests

# Operations
npm run ops:verify-live     # verify the real configured services before go-live
npm run ops:backup          # database backup with manifest
npm run ops:restore-verify  # restore drill with checksum verification

CSV import templates are in templates/csv: suppliers, purchase orders, price agreements, approved charges and receipts.
